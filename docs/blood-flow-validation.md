# Blood-flow animation: scope and validation

작성일: 2026-10-23 (Asia/Seoul). 이 문서는 교육용 혈류 입자 표현의 구현 계약과 검증 범위를 기록한다. 임상 검증, 해부학 전문가 승인, 유체역학 검증 문서가 아니다. 실제 브라우저 검수와 최종 명령 실행 결과는 아래 상태표에 별도로 기록한다.

## 구현과 계산의 경계

기존 HRA 정적 아틀라스 위에 WebGL 입자를 표시한다. Blender 4.5 LTS CLI는 설치되어 있으며 자산 생성·내보내기에 사용할 수 있지만, 이 기능의 입자 이동은 브라우저에서 생성한다. Blender에 애니메이션을 굽거나 GLB·원본 메시·심실 벽·판막 형상을 변경하지 않는다.

- 경로 정의: `src/flow/paths.ts` — 아틀라스의 명명된 구조 경계 상자 안의 기준점과 수동 가이드 점으로 만든 12개 경로.
- 시간 신호: `src/flow/timeline.ts` — 기존 0D 모델의 부호 있는 구획 유량(mL/s)을 구간별 선형 보간하고 해석적으로 적분한다.
- 표현: `src/BloodFlow.tsx` — Catmull–Rom 가이드, 인스턴스 입자, 짧은 잔상, 선택적 경로선을 렌더링한다.
- 시간 제어: `src/App.tsx` — 그래프·수치와 같은 기록 샘플을 사용하며, 반복 주기 수를 누적해 주기 경계에서 입자 이동량을 되돌리지 않는다. 스크럽은 선택 시점으로 이동하고 일시정지한다. 새 계산 결과가 오면 이전 결과의 누적 이동량을 폐기한다.

입자의 경로 진행량은 부호 있는 누적 유량 적분을 고정 그래픽 계수인 90 mL당 한 경로 길이로 환산한다. 결과별 최대 유량으로 정규화하지 않으므로 계산 유량이 감소하면 같은 시간 동안 이동량도 감소한다. 이 계수는 실제 거리, 유속, 체류 시간, 적혈구 크기 또는 개수를 의미하지 않는다. 경로의 길이가 다르므로 화면상의 이동 거리로 경로 간 유속을 비교할 수 없다. 표시 입자 개수는 경로 길이와 밀도 설정에 맞추되 최소 12개로 정한다. 입자 밀도 설정은 그래픽 개수만 바꾸며 계산 혈액량·유량에는 영향을 주지 않는다.

## 순환 방향과 생리학적 의미

전신에서 돌아온 산소가 적은 혈액은 대정맥 → 우심방 → 삼첨판 → 우심실 → 폐동맥판 → 폐동맥을 거쳐 폐로 간다. 폐에서 산소를 받은 혈액은 폐정맥 → 좌심방 → 승모판 → 좌심실 → 대동맥판 → 대동맥을 거쳐 전신으로 간다. 동맥/정맥 구분은 심장에서 나가는지 돌아오는지에 따른 것으로, 폐동맥은 산소가 적고 폐정맥은 산소가 많은 혈액을 운반한다. [NHLBI: How Blood Flows through the Heart](https://www.nhlbi.nih.gov/health/heart/blood-flow)

판막을 지나는 입자 이동은 고정된 수축기·이완기 시간표가 아니라 해당 시점의 계산 유량으로 결정한다. 유량이 0인 구간에서는 누적 이동량이 변하지 않는다. 정맥 유입까지 심실 박출 여부와 함께 일괄 정지시키지 않는다. 정상 판막의 역류 방지 기능과 심방·심실의 박출 순서는 설명 근거로만 사용하며, 이 기능은 실제 판엽 운동이나 전기생리를 계산하지 않는다. [NHLBI: How the Heart Beats](https://www.nhlbi.nih.gov/health/heart/heart-beats)

승모판 유량의 양수는 LA → LV, 음수는 LV → LA를 뜻한다. 승모판 역류 시나리오에서는 대동맥 전방 흐름과 좌심방으로의 역방향 흐름을 동시에 표시할 수 있다. 역류는 일부 혈액이 수축하는 좌심실에서 좌심방으로 되돌아가는 현상이다. [American Heart Association: Mitral Valve Regurgitation](https://www.heart.org/en/health-topics/heart-valve-problems-and-disease/heart-valve-problems-and-causes/problem-mitral-valve-regurgitation)

폐정맥 유량도 부호 있는 신호이다. 현재 기준 매개변수의 기록 주기에서는 약 −81.09~185.40 mL/s이며, 일부 구간에 모델이 계산한 정맥 역방향 흐름이 있다. 이를 0으로 잘라내거나 승모판 역류로 오인하지 않는다. 이 수치는 현재 교육용 0D 모델 출력이며 임상 정상 범위나 측정 자료가 아니다. 대정맥 입력 신호도 부호를 보존한다.

## 12개 경로의 평가

아래 화살표는 양의 유량에 해당한다. 음수 신호는 같은 경로의 반대 방향 이동을 만든다.

| 경로 ID | 연결 | 계산 신호 | 평가 범위와 제한 |
| --- | --- | --- | --- |
| `caval-superior` | SVC → RA | `systemicVenous` | 상대정맥 기준점과 우심방 가이드 연결 |
| `caval-inferior` | IVC → RA | `systemicVenous` | 하대정맥 기준점과 우심방 가이드 연결 |
| `tricuspid` | RA → TV → RV | `tricuspid` | 명명된 삼첨판 기준점을 통과 |
| `pulmonary-outflow` | RV → PVvalve → PT | `pulmonary` | 명명된 폐동맥판 기준점을 통과 |
| `pulmonary-left` | PT → LPA | `pulmonary` | 폐동맥줄기 가이드에서 좌폐동맥 방향으로 연결 |
| `pulmonary-right` | PT → RPA | `pulmonary` | 폐동맥줄기 가이드에서 우폐동맥 방향으로 연결 |
| `pulmonary-venous-rs` | RSPV → LA | `pulmonaryVenous` | 우상폐정맥 기준점과 좌심방 가이드 연결 |
| `pulmonary-venous-ri` | RIPV → LA | `pulmonaryVenous` | 우하폐정맥 기준점과 좌심방 가이드 연결 |
| `pulmonary-venous-ls` | LSPV → LA | `pulmonaryVenous` | 좌상폐정맥 기준점과 좌심방 가이드 연결 |
| `pulmonary-venous-li` | LIPV → LA | `pulmonaryVenous` | 좌하폐정맥 기준점과 좌심방 가이드 연결 |
| `mitral` | LA → MV → LV | `mitral` | 명명된 승모판 기준점을 통과; 음수에서 역방향 |
| `aortic-outflow` | LV → AV → AO → ARCH → DAO | `aortic` | 명명된 대동맥판·대동맥 구조 방향으로 연결 |

각 대정맥 경로는 하나의 `systemicVenous` 신호를, 각 폐정맥 경로는 하나의 `pulmonaryVenous` 신호를 공유한다. 폐동맥줄기 및 좌우 가지도 하나의 `pulmonary` 신호를 공유한다. 이는 같은 구획 연결을 여러 공간 가이드에 중복 표시한 것이다. 가지별 유량 배분을 계산하거나, 입자 수를 합산해 실제 총 유량을 구할 수 없다.

대동맥 하행부까지의 가이드와 폐동맥 가지가 각각 판막 유량을 따르는 것은 구획 연결의 박동 표현이다. 탄성 동맥 안에서 위치마다 달라지는 국소 유동이나 이완기에 지속되는 관류를 재현하지 않는다. `systemic` 및 `pulmonaryBed` 신호는 수치 계산에 남아 있지만, 아틀라스에 전신·폐 미세혈관 형상이 없으므로 대응하는 3D 경로를 만들지 않는다. 폐동맥과 폐정맥 또는 대동맥과 대정맥을 허공의 폐쇄 루프로 연결하지 않는다. 관상혈류는 이 0D 모델의 별도 계산 대상이 아니므로 입자 경로를 추가하지 않는다.

## 검증하지 않은 내용

경계 상자 기준점과 연결 순서 검사는 올바른 구조 이름을 참조하는지만 확인한다. 가이드가 실제 혈관 내강 안에 있는지, 벽·중격·판엽을 침범하는지, 입자 반경이 내강에 맞는지는 증명하지 않는다. 곡선 제어점이 아틀라스 전체 경계 안에 있다는 사실도 곡선 전체의 내강 포함을 보장하지 않는다. 따라서 이 경로는 추출된 혈관 중심선이나 혈류 영상 기반 궤적이 아니다.

CFD, Navier–Stokes 해, 와류, 난류, 국소 속도장, 벽 전단응력, 협착 제트, 산소포화도, 실제 적혈구 추적, 유체와 심근의 상호작용을 계산하지 않는다. 입자가 경로 끝에서 반복되고 여러 경로에 독립적으로 배치되므로 개별 입자를 하나의 혈구로 추적하거나 개수를 통해 질량 보존을 검증할 수 없다. 혈액량 보존은 기존 0D 수치 모델에서 별도로 검사한다.

청록·적색은 산소가 적은/많은 순환을 구분하는 도식 색이며 실제 혈액 색이나 산소 측정값이 아니다. 승모판 역류의 강조색은 역방향 이동을 구별하기 위한 그래픽 표기이다. 정적 아틀라스의 반투명 모드는 내부 입자를 보기 위한 표시 효과이며 조직·벽 두께·실제 수축을 변경하지 않는다. [기존 해부학 검증 범위](ANATOMICAL_VALIDATION.md)와 [0D 계산 모델 한계](physiology-model.md)가 계속 적용된다.

권장 화면 설명:

> 입자는 계산된 구획 유량의 방향과 상대적 변화를 나타내는 교육용 표현입니다. 경로·입자 속도·크기는 실제 혈구 궤적이나 유속이 아니며, 산소포화도·3D 유동장은 계산하지 않습니다.

## 상호작용 계약

- 전체/우심/좌심 필터, 가이드 선, 입자 밀도, 반투명 해부학 표시를 제공한다.
- 혈류 표시 끄기는 입자 계층만 숨긴다. 그래프 재생을 중지하지 않는다. 뷰어의 재생·일시정지 버튼은 전역 시간 제어와 같은 상태를 사용한다.
- 일시정지는 입자 위치·강조·잔상과 그래프·수치 시점을 함께 고정한다. 시간 슬라이더 또는 그래프 선택도 일시정지한다. 0.25×/0.5×/1×는 하나의 공유 재생 속도에 적용한다.
- 초기 자동 재생은 `prefers-reduced-motion: reduce`일 때 시작하지 않는다. 시나리오나 매개변수 변경은 일시정지한다.
- 새 계산 대기, 오류, 모델 해석 범위 밖 상태에서는 이전 수치 결과와 입자 표현을 숨긴다. 재계산 후 새 유량 적분 표를 사용하며 이전 계산의 누적 이동량을 이어 붙이지 않는다.
- 경로가 참조하는 구조 중 하나라도 사용자가 직접 숨기면 해당 경로를 숨긴다. 구조 초점 보기 및 관상혈관 보기에서는 전체 순환 경로를 억제한다. 반투명/내부 구조 표시와 사용자의 개별 숨김은 구분한다.
- 동일한 절단면과 유지 방향을 메시·입자·가이드 선에 적용한다. 입자와 가이드가 해부학 구조의 선택을 가로채지 않는다.

### 실제 브라우저에서 확인한 계산 시점

### 실제 브라우저에서 확인한 시간 제어

- 일시정지 후 실제 시간이 흘러도 `ejection-84ms.png`와 `ejection-paused.png`가 바이트 단위로 같았다. 42 → 172 → 42로 스크럽한 `scrub-return.png`도 같았다. 세 파일의 SHA-256은 `dfb4784ae3482f6cd216d3fd1aebc3077695fc60c193a63f5f535984ac23e6ff`이다.
- 1×로 여러 주기를 재생한 뒤 index 39(78 ms)에 멈추고, 이미 선택된 압력–용적 그래프 점을 다시 눌렀다. 첫 클릭은 누적 주기 위치를 첫 주기의 같은 시점으로 되돌려 이미지를 즉시 바꾸었다. 같은 점을 반복 클릭한 두 캡처는 바이트 단위로 같았다. 이는 동일한 샘플 인덱스에서 참조 시간만 초기화될 때도 캔버스가 갱신되는 `inspectionRevision` 회귀 검수이다.
- 위 회귀 증거에서 `multiple-cycles-paused.png` 해시는 `bf76de7b58dc27e412ad518afb52ea8ecd340a4c3d497a39cb55465b2d17c0fa`, `same-index-inspect.png`와 `same-index-inspect-repeat.png`의 공통 해시는 `5ce98aa0508af319fd1beaf583d8a5ebd300dc071979560a3250d9c35fb6dba0`이다. 반복 재생의 누적 위치와 첫 주기로 다시 스크럽한 위치는 의도적으로 다르다.
- 0.25×/0.5×/1× 선택과 각 속도에서 샘플 인덱스 증가를 확인했다. 기록은 `speeds.json`이다. 이 확인은 정밀 시간 비율, 프레임률 또는 GPU 성능 벤치마크가 아니다.

### 실제 브라우저에서 확인한 표시와 재계산

- 전체/우심/좌심은 각각 12/6/6개 경로를 표시했다. RA를 직접 숨기면 43개 메시와 9개 경로가 남았다. 판막 초점은 경로를 숨겼으며 초기화로 복원되었다.
- Z 절단면과 유지 방향 반전이 메시와 입자를 함께 잘랐다. 혈류 끄기, 반투명 해부학 끄기, 불투명도 25%, 밀도 1.5, 가이드 선 끄기를 확인했다. 회전·확대와 RV 구조 선택도 동작했다. 관련 캡처는 `right-circulation.png`, `left-circulation.png`, `clipped-flow.png`, `clipped-flow-flipped.png`, `flow-off.png`, `opaque-anatomy.png`, `anatomy-opacity25.png`, `high-density-no-guides.png`, `rotated-flow.png`, `zoomed-flow.png`이다.
- HFrEF 시나리오에서 심박수 120, 수축력 0.6, 이완기 강성 1.5, 전신 저항 1.6, 혈액량 5500 mL, 기전 강도 1 조합으로 변경했다. 계산 대기 중에는 이전 결과가 모두 숨겨졌고, 최종 해석 범위 오류에서도 뷰어가 표시되지 않았다(`viewerVisible=false`). 기준 상태 초기화 후 뷰어가 복원되었다. Worker 실패를 강제로 발생시키는 검사는 수행하지 않았다.
- 모바일 390×844에서 가로 넘침 없이 `scrollWidth=390`이었고 필터 터치가 동작했다(`mobile.png`). 데스크톱 1440×1050에서도 확인했다. reduced-motion은 코드 처리만 확인했으며 OS/브라우저 에뮬레이션 검수는 수행하지 않았다.
- 브라우저 콘솔에는 기존 `THREE.Clock` 사용 중단 예정 경고만 관찰했다. 빌드에는 500 kB를 넘는 3D 뷰어 청크 경고가 남아 있다. 프레임률·발열·장시간 재생 성능을 측정하지 않았다.

이 작업의 성공은 연결된 0D 신호를 일관되게 표현하고 제어할 수 있음을 뜻한다. 경로의 해부학적 승인이나 교육 배포 승인을 부여하지 않으며 기존 `verify:release` 승인 게이트를 완화하지 않는다.
